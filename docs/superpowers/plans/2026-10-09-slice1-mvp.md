# Slice 1: MVP (Character + Inventory + Preview) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Usable MVP — edit character stats, manage weapons/items/bank, preview selection in the g3n viewport.

**Architecture:** Extend headless `session` with inventory view-models + mutation wrappers (all unit-tested); build `ui` TabBar shell with CHARACTER and INVENTORY tabs plus preview-mode switching. Mutations re-extract in-process and patch widgets.

**Tech Stack:** Go 1.25, g3n v0.2.0 (pinned), `bl2save/desktop` module.

**Spec:** `docs/superpowers/specs/2026-10-09-g3n-redesign-design.md` (§§2–4; MVP scope)

## Global Constraints

- Same-module placement (`desktop/native/...`); `desktop/internal/*` read-only.
- Fixture: `desktop/tests/Save0001.sav` — mutation tests copy it to `t.TempDir()` first, never mutate the fixture.
- Tests never touch the real user config; `go test ./...` + `go vet` green before each commit.
- Item `info` from `ExtractInventory` is a `*bl2save.ItemInfo` struct — session converts via `encoding/json` round trip to `map[string]any` before `ResolveItemParts` (bridge's direct type assert does not survive the struct; do not copy that pattern).
- No mask/MIC texture compositing in this slice (deferred ruling below); no Gibbed UI, loadouts, wizard, menus menubar (slice 3).
- Preview uses a procedural mesh until owner-extracted assets exist (slice 3); runbook proves mode-switching + materials on it.

## Slice-1 Rulings (locked)

- R1: Mask/MIC compositing (spec §2) deferred to slice 2 — MVP materials are flat PBR rarity/element colors; skin tint applies flat zone colors only. Cost if wrong: preview looks flat until slice 2 (accepted).
- R2: Every session mutation checks `platform.IsGameRunning()` first and returns its error (spec §4 guard). The game-running==true path is not unit-testable headless — covered by runbook step.
- R3: `OpenSave` grows into the full view load (character + inventory in one read); inventory is `map[string][]ItemView` keyed `"weapons"|"items"|"bank"`.

## Review Focus

1. Mutation while BL2 runs → blocked with error, file untouched. (Runbook; untestable headless.)
2. Negative currency / out-of-range level input → backend clamps; session returns re-extracted (clamped) values, never an error for clamping. (Test: Task 2.)
3. Delete/duplicate/transfer with bogus index or same-field transfer → error, no write. (Test: Task 3.)
4. Item whose parts don't resolve (no Gibbed data) → row still lists with display-name fallback, no crash. (Test: Task 1 — assets.New("") with empty gibbed dir.)
5. Preview with no model file present → CTA label, app alive. (Runbook.)

**Files:**

- Consumes: `Store.ExtractInventory(tree)`, `assets.DB.ResolveItemParts(map)`, `DB.BuildDisplayName`, `DB.EstimateWeaponStats` (existing).
- Produces (exact):
```go
type ItemView struct {
    Index, Field int
    DisplayName, RarityName, RarityColor, ElementName string
    Level int
    Manufacturer, Category string
    IsWeapon bool
    Stats map[string]any // estimated_stats for weapons, nil otherwise
}
// SaveView gains: Inventory map[string][]ItemView
```
Mapping: `info` struct → JSON round trip → map; `resolved["display_name"]`, `resolved["rarity"].(map[string]any)["name"/"color"]` (rarityInfo marshals with json tags), `resolved["element"]` nil-or-map `["name"]`, `Level` = int(`info["level"].([]any)[0])`, `Stats` = `resolved["estimated_stats"]` for weapons. Missing keys → zero values, never error (Review Focus 4).
